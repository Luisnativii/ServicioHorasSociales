`admin/` implementa persistencia del único rol ADMIN con múltiples cuentas. `repository.go` usa consultas generadas de `db/`, normaliza/valida correo y traduce errores sin revelar SQL. El hash se excluye de JSON y no se consulta en listados. Los handlers futuros deben usar DTOs explícitos, nunca serializar modelos SQL.

`catalogos/` persiste los catálogos independientes de tipos de proyecto y áreas. Conserva el nombre visible recortado, rechaza duplicados por mayúsculas/minúsculas dentro de cada catálogo y permite desactivar sin borrar. No incluye semillas, relaciones entre ambos catálogos ni referencias de proyecto.

`cmd/admin` implementa altas exclusivamente por herramienta Docker con el hashing de `internal/platform/password`. `internal/platform/auth` emite y valida JWT; el router protege el grupo privado y transporta la identidad verificada por contexto. Los módulos se registran con `Options.RegisterPrivate`. No hay todavía login ni módulos de negocio. `scripts/check-admin.sh` prueba el repositorio con PostgreSQL real y rollback; `check-admin-cli.sh` comprueba el CLI y retira solo las cuentas sintéticas creadas por esa ejecución en hs-test. Las pruebas sin indicador explícito no conectan a desarrollo.
